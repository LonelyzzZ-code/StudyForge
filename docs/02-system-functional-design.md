## 二、用户功能规格

### F1 模型配置（P0）

- 三环节（planner / generator / grader）分别配置 `base_url + api_key + model`
- 配置界面提供**连通性测试按钮，可无限次测试**（每次发一次最小调用验证可用）
- key 只存本地、不写日志

### F2 学习请求（P0）

- 结构化表单四个字段：学习目标、现有基础、期望成果、可用时间
- 领域识别：自动判断（MVP 仅支持 code），用户可手动改
- 范围外请求（如「学做饭」）：拒绝并列出支持的领域
- 提交 → 创建路线任务 → 跳转路线详情页

### F3 路线管理（P0）

- **DAG 可视化**：知识点用节点表示，箭头和线指示学习路线
- 节点状态：锁定 / 未开始 / 学习中 / 已通过 / 已掌握 / 已删除 / 生成中
- **硬解锁**：节点在后继的所有前驱节点通过后解锁；线性路线即「完成当前节点测验才解锁下一个」
- 手动调整：
  - **删除节点（自动重连）**：删除有后继的节点时，后继依赖自动重连到被删节点的前置上（如 `A→B→C` 删 B 变 `A→C`），弹窗展示影响面，确认后执行；无后继节点直接删
  - **标记已掌握**：免测验直接视为通过，后继照常解锁
  - **重生成分支**：以某节点为根重新生成子图
- 多路线并存；**首页为创建路线页**，路线列表放导航入口

### F4 内容学习（P0）

- 节点页渲染讲义（按领域模板的结构化小节），显示生成状态徽标（就绪 / 生成中 / 存疑）
- 「这段没懂」反馈：选中段落触发定点重生成（**P1**）

### F5 节点测验（P0）

- 两档题库与解锁线（统一 **85%**）：
  - 概念记忆档（选择 / 填空）→ 正确率 ≥85% → 解锁基础理解档
  - 基础理解档（选择 / 填空 / 一句话简答）→ 正确率 ≥85% → **节点通过 → 解锁后继节点**
- 判分：
  - 客观题：代码规则判分，即时显示
  - 简答：grader 判分，展示通过与否 + 命中关键点 + 引用答案原文的理由
- **错题两级流程**：
  1. 答错一道题 → 系统继续出**同标签的基础题**（同考点、基础难度），循环出题直到答对
  2. 答对之后 → 出**变式题**（换情境）检验是否真正掌握
- 薄弱点：同标签累计错 ≥2 次 → 节点内提示重学该知识点
- 重学后再测：出变式题，不出原题（防背题）

### F6 实践任务（P0，轻量）

- 展示任务书（目标 + 要求 + 自查清单），用户自行实现、自行标记完成
- 不判分、不阻塞节点通过（节点通过只看两档测验）

### F7 进度总览（P0 简版）

- 路线维度：节点完成数 / 总数（不做预计剩余时长）

### F8 成本可观测（P0 简版）

- 每次调用记账（环节 / 用途 / token 数 / 耗时）
- 路线维度累计展示；成本预估（**P1**）

### F9 技术热点（P0，v1.1 增补）

- **定位：学习入口，不是资讯站**——展示计算机领域值得关注的技术方向，帮用户决定「学什么」，与学习路线闭环打通
- 数据来源：**内置分类榜单**（随版本更新，离线可用；不依赖外部服务与 API key）
  - 分类：AI 与大模型 / 编程语言与运行时 / 前端与客户端 / 云与基础设施 / 数据与数据库 / 安全等
  - 每条热点：名称、一句话说明、为什么值得关注、适合谁、建议起点
- 交互：分类筛选、关键词搜索、卡片展开详情
- **「去学习」一键联动**：每条热点可一键跳转创建路线页，学习目标预填（如「学习 Rust 语言核心与异步编程」），用户补充基础/时间后提交——回到 F2 主线
- 热点榜单与领域边界一致：仅收录 code 领域方向；P2 可选接入 GitHub Trending 等外部源增强实时性

### F10 学习问答（P0，v1.1 增补）

- 学习过程中**随时呼出问答窗**（节点学习页悬浮按钮 → 侧边抽屉），向 AI 提问当前不懂的问题
- 上下文自动携带：当前节点标题、知识点标签、讲义摘要（+ 测验中当前题目），AI 回答贴合所学内容
- 对话式多轮：保留会话历史（前端持有，后端无状态），可随时清空重新开始
- **流式输出**（打字机效果），演示模式下返回与当前节点相关的预置回答
- 模型环节为 **assistant**（第四环节）：默认继承 generator 配置，可单独指定；记账 purpose=assistant
- 引导聚焦：system prompt 引导优先解答与当前学习内容相关的问题（不硬性拒绝）

## 三、引擎功能规格

### E1 路线生成流水线（P0）

- 输入：学习请求 + 领域模板
- 过程：planner 生成 DAG → 代码校验（无环 / ID 有效 / 请求目标有对应节点覆盖）→ 失败带原因重试（上限 3 次）→ 持久化
- 输出：Roadmap + 全局大纲（各节点摘要级描述，作为后续生成的上下文）

### E2 内容预生成流水线（P0）

- 路线创建即自动启动
- 按 DAG 拓扑顺序逐节点生成，上下文 = 领域模板 + 节点定义 + 全局大纲 + 直接前序摘要
- 每节点生成后质检：知识点覆盖率 / 结构完整性 / 与前序 embedding 重复度
  - 不通过 → 带原因重生成（上限 2~3 次）→ 仍失败 → 置「存疑」放行
- 就绪窗口跟随学习进度：始终保证当前节点 + 后续 3~5 个节点就绪，不全量生成
- 队列状态持久化，中断可恢复
- 与路线手动调整联动：节点删除 / 重生成分支 → 作废或重排队列中相关任务

### E3 判分与错题处理（P0）

- 客观题：规则判分
- 简答：grader 调用（题目 + 标准答案 + 关键点清单 + 用户答案 → 命中情况 + 结论 + 理由），低 temperature
- 同标签基础题 / 变式题生成（generator 子模式）：同考点换情境、相似度落区间、不泄露答案
- 错题按 knowledge_points 标签聚合统计，≥2 次触发薄弱点标记

### E4 领域模板包管理（P0：code；P1：language / exam）

- 模板包内容：内容结构模板（讲义小节结构）、题型配比、掌握度阈值
- 加载时结构校验，合法才可用
- 领域枚举 + 超域拒绝
- **MVP 只实现 code（编程）模板包并打磨好，language / exam 随后补**

### E5 模型接入与调度（P0）

- 四环节路由配置（planner / generator / grader / assistant；assistant 未单独配置时继承 generator）
- structured output 降级链：native → JSON mode → prompt 内嵌 schema + 解析失败重试
- 上下文窗口预算裁剪（优先级：节点定义 > 模板 > 前序摘要 > 全局大纲）
- 并发控制 + 429 退避重试 + 队列可暂停/恢复
- 前台请求（判分 / 变式题）优先于后台预生成
- token 记账：每次调用记录环节 / 用途 / token 数 / 耗时

### E6 数据持久化（P0）

- 路线、内容包（带版本）、题目与标签、答题记录、错题统计、进度、调用记账
- 存储选型归 03 架构设计

## 四、页面信息架构（P0）

```
创建路线页（首页，表单）
技术热点页（榜单 + 去学习一键预填）
路线详情页（DAG + 进度 + 生成状态）
节点学习页（讲义 | 测验 | 实践任务 三个 tab + 问 AI 悬浮窗）
路线列表页（导航入口）
设置页（模型配置）
```

## 五、功能设计决策记录（2026-10-15 确认）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 学习请求输入形式 | 结构化表单（四字段），非自由文本 |
| 2 | 删除有后继节点 | 方案 a：后继依赖自动重连到被删节点前置 + 影响提示确认 |
| 3 | 错题处理 | 两级：答错 → 同标签基础题循环直到答对 → 再出变式题检验 |
| 4 | 重学后再测 | 出变式题，不出原题（防背题） |
| 5 | 节点解锁 | 硬解锁：前驱全部通过才解锁后继；正确率门槛统一 85% |
| 6 | 简答未通过 | 可重答，或查看答案后标记重学 |
| 7 | 实践任务 | 不判分、不阻塞节点通过 |
| 8 | 领域范围 | MVP 只做 code 模板包，language / exam 为 P1 |
| 9 | 首页 | 创建路线页 |
| 10 | 进度展示 | 不做预计剩余时长 |
| 11 | 技术热点数据源（2026-10-19） | 内置分类榜单（离线可用、随版本更新），P2 再考虑外部源；每条热点可一键预填创建路线 |
| 12 | 学习问答（2026-10-19） | 新增第四 LLM 环节 assistant（用户主动、流式、带节点上下文）；默认继承 generator 配置；会话历史前端持有 |
